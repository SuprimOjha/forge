# Documentation style

Write for readers who have not seen the implementation. Prefer short headings, complete examples, explicit prerequisites, and clear risk descriptions.

- Do not claim a command supports an option unless source confirms it.
- Mark platform-specific instructions.
- Use fenced code blocks with language labels where practical.
- Explain destructive behavior before showing commands.
- Keep filenames and paths consistent.
- Update command references when commands change.

Documentation should explain the product accurately rather than advertise unverified capabilities.
